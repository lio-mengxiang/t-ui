<H2 className="mt-0">Anchor 组件的核心原理</H2>

**Anchor 组件是前端实现页面内定位导航的关键技术，也是构建现代 Web 应用的基础能力之一。**

想象这样一个场景：你需要开发一个组件，让任意一个 DOM 元素能够：

- 在用户交互时，自动滚动到页面或某个滚动容器的指定位置；

- 或在 URL 跳转后，精准定位到页面或滚动容器的目标区域。

虽然浏览器原生支持锚点跳转，但功能较为局限，因此当前主流的前端库普遍采用自定义 `Anchor` 方案来实现更灵活、更强大的定位功能。这背后涉及多个技术挑战，具体可参考下文「技术难点」部分。

## 技术难点

- 如何设计高扩展性的 Anchor 组件架构？

  - 例如支持用户完全自定义 Anchor.Link，而不必依赖 @t-headless-ui/react 提供的默认实现。

- 如何同时支持滚动到 window 与任意 DOM 容器？

  - 实现对不同滚动环境的统一抽象与兼容。

- 如何处理滚动过程中的“竞态问题”？

  - 例如用户点击“标题C”后页面平滑滚动，中途经过“标题A”和“标题B”时，scroll 事件监听可能错误触发高亮切换，导致导航状态“乱跳”。

- 如何优化滚动事件的触发频率，避免性能损耗？

  - 例如使用 requestAnimationFrame 优化滚动动画，避免频繁触发 scroll 事件。

- 如何支持页面加载后自动滚动到 URL hash 对应的位置？

  - 例如监听 DOMContentLoaded 事件，在页面加载完成后，根据 URL hash 滚动到目标位置。

- 当多个标题同时出现在视口内，如何准确判断当前激活项？

  - 例如使用 IntersectionObserver 监听标题元素是否进入视口，从而准确判断当前激活项。

- 如何结合 useState 与 Promise（如 useStateWithPromise Hook），确保 onChange 事件在激活标题时稳定触发？

  - 例如在 onChange 事件中，使用 Promise 确保状态更新完成后再触发回调函数。

锚点 Anchor
通过锚点可快速找到信息内容在当前页面的位置。

前言

在原生 JavaScript 和 HTML 中，其实锚点跳转（Anchor / Hash 跳转）功能本身就存在，但存在一些问题，所以我们研发自定义的 Anchor 组件。

我们先来介绍一下原生的锚点跳转功能。

一、什么是锚点跳转？

一句话概括： 点击一个链接，页面会自动滚动到指定位置。这个“指定位置”，就是锚点。

在浏览器里，锚点通常表现为 URL 里的 #xxx：

1https://example.com/page#section1

#section1 就是锚点，浏览器会尝试找到页面中“叫这个名字”的位置，然后滚过去

最基础的用法，给目标位置一个 id：

1<h2 id="section1">第一章</h2>

然后用 a 标签指向它:

1<a href="#section1">跳到第一章</a>

然后当你点击链接时，浏览器会：

  • 修改地址栏的 hash（#section1）

  • 查找 id="section1" 的元素

  • 自动滚动页面，让它出现在视口中

不需要任何 JavaScript。

二、原生锚点的局限性

固定头部会遮挡内容

这个是非常常见的问题，假设你们的网站头部是固定的，那么当你点击锚点跳转时，目标位置会被头部遮挡。你们网站头部是一个 css 如下的固定样式：

1header { 2 position: fixed; 3 top: 0; 4 height: 64px; 5}

那么当你点击锚点跳转时，目标位置会被头部遮挡。例如：

1<a href="#section1">跳到第一章</a>

浏览器的行为是：把 section1 的 顶部 对齐到视口顶部。结果就是：标题刚好被 header 挡住。

无法在容器内滚动

有时候我们滚动的对象不是 window 而是指定某个容器，必须要求锚点在这个容器内才行，但这个是很不友好的，因为锚点往往是页面最外面（fixed 或者 sticky）布局 然后点击跳转到指定容器内的元素。

没法做滚动监听

也就是我们滚动过程中，到底滚动到了哪个位置，然后响应的锚点元素高亮，代表当前滚动到了哪个位置。原生是不支持的

三、Anchor 组件的设计

我们的 Anchor 组件，会解决原生锚点的这些问题。这里简单描述一下解决思路：

头部遮挡内容问题

解决思路是，不要让浏览器决定滚到哪里，而是自己算。核心思路如下

1const scrollTop = getScrollTop(container); 2const offsetTop = getOffsetTop(element, container); 3 4// 👇 关键点 5const targetScrollTop = scrollTop + offsetTop + offset;

如果容器不是 window, 使用容器的 scrollTop 属性就能得到容器当前的滚动高度。

然后获得 offsetTop 值（当前元素到容器的距离）： getScrollTop 逻辑的核心是判断如果 container 不是 window, 那么当前元素和这个 container 顶部的距离公式就是

当前元素的 getBoundingClientRect().top 就是当前元素距离容器顶部的距离。减去容器的 getBoundingClientRect().top 值，就是当前元素距离容器顶部的距离。

最终，我们可以得到当前元素需要滚动的值：

1const targetScrollTop = scrollTop + offsetTop;

上面的公式能确保当前元素滚动到容器的顶部，但有时候我们不想让它滚动到顶部，而是滚动到容器顶部的某个位置。

所以我们可以在上面的公式基础上，再加上一个 offset 值，就是滚动的偏移量。从而得出：

1const targetScrollTop = scrollTop + offsetTop + offset;

上面举例的是容器非 window 的情况下，如果是 window 那么 scrollTop 就是 window.pageYOffset。也很简单。

在容器内滚动问题

上面也算提到了如何解决无法在容器内滚动的问题。核心思路就是，当前元素滚动到容器顶部的某个位置，就是当前元素距离容器顶部的距离加上 scrollTop。

滚动监听问题

我们会在滚动过程中，监听滚动事件，然后判断当前滚动到了哪个位置，然后响应的锚点元素高亮，代表当前滚动到了哪个位置。

核心架子

这个小小的组件有很多技术细节，后面的小结部分有一些描述，这里浅谈一下组件库开发中一个常见的技术套路：订阅-发布模式。

之前我们说了 <Anchor.Link> 组件，它会收集所有要定位的目标元素。具体代码上是如何实现的呢？我们来说说细节：

首先，我们需要一个 AnchorContext 上下文，用来存储所有要定位的目标元素。使用方式如下：

1'use client'; 2import { forwardRef, type PropsWithChildren } from 'react'; 3//... 省略各种 import 依赖 4 5import type { AnchorProps } from './interface'; 6 7export const Anchor = forwardRef((props: PropsWithChildren<AnchorProps>, ref) => { 8const { 9 // 参数省略 10} = props; 11 12// 收集所有要定位的目标元素 13const linkMap = useRef<Map<string, HTMLElement>>(new Map()); 14 15return ( 16 <AnchorContext.Provider 17 value={ 18 linkMap, // 这里是关键 19 // 其它传参省略 20 }} 21 > 22 <div {...restProps} ref={useComposedRefs(wrapperRef, ref)}> 23 {children} 24 </div> 25 </AnchorContext.Provider> 26); 27});

以上代码中 linkMap 是一个 Map 数据结构，就是用来收集数据的。

如何收集呢？我们看 Anchor.Link 组件的实现：

1'use client'; 2 3import { forwardRef, useContext, useEffect, useRef, type PropsWithChildren } from 'react'; 4import { AnchorContext } from './context'; 5// 省略其它参数 6 7export const AnchorLink = forwardRef<HTMLDivElement, AnchorLinkProps>((props: PropsWithChildren<AnchorLinkProps>, ref) => { 8// 获取上面 Provider 传下来的参数 9const anchorContext = useContext(AnchorContext); 10// ref 11const linkRef = useRef<HTMLDivElement>(null); 12 13// 这里是核心，收集所有要定位的目标元素 14useEffect(() => { 15 addLink(linkMap, targetId, linkRef.current); 16 return () => { 17 removeLink(linkMap, targetId); 18 }; 19}, [targetId, linkMap]); 20 21return ( 22 <div 23 // 省略其它参数 24 data-target-id={targetId} 25 className={currentId === targetId ? activeClassName : className} 26 > 27 {children} 28 </div> 29); 30});

注意上面的 useEffect, 其中 addLink 函数，实际上做的就是类似 linkMap.set(targetId, linkRef.current) 这样的操作。这样 linkMap 就收集到所有的锚点元素了。

这种套路，在 Checkbox 组件, ant design（或者说国内主流组件库） 的Form中都是这样来利用 发布-订阅模式，来控制组件之间的状态同步的或者收集所有子元素的。

小结

还有一些其它问题，就不一一赘述了，例如：

  • 没有提供回调函数，当滚动完毕后，我们想做一些事情，例如滚动到某个位置后，这时候，我们可以提供一个回调函数 onChange，当滚动完毕后，会调用这个函数。
  • 点击跳转锚点后，如何跳转？
  • 点击跳转时，也触发了滚动事件，如何阻止滚动事件？(不阻止滚动事件会有一些意想不到的 bug)
  • 如果做到初始化的时候，直接跳转到指定的锚点位置？
